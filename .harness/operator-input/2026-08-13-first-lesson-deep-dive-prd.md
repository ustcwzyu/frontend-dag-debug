# PRD：把 Agent 入门第一课深化为可学习、可实践、可交付的课程

## Objective

将入门路线第一课从“概念导览 + 三步纸面练习”深化为一节完整的中文静态课程。学习者应能在不依赖后端、网络、账号或 API key 的前提下，理解模型调用与 Agent Run 的边界，阅读一条可验证的 run 轨迹，独立写出研究助手 v0 的任务合约，完成一次本地文本实验，并用明确的评估量表判断结果是否合格。

课程定位：面向有基础开发经验、第一次系统学习 Agent 的学习者；预计 60–90 分钟；仍是单页中的可见 section，不新增多页面路由或真实模型调用。

## Scope

### 1. 课程导航与学习承诺

- 第一课头部明确：适合人群、预计用时 60–90 分钟、前置知识、完成后能力、课程产物。
- 展示一条六段学习路径：概念 → 拆解 → 设计 → 实验 → 评估 → 复盘；每段有目的、学习动作和产出。
- 把“读完”与“完成”区分开：完成必须交付任务合约、冻结输入记录、执行记录、评估表和复盘结论。

### 2. 概念讲解：从模型调用到 Agent Run

- 解释模型调用的输入、输出、上下文窗口和不具备的能力；说明“文本生成”不自动等于 Agent。
- 用对照表比较单次模型调用与 Agent Run：目标、状态、步骤/工具、停止条件、输出、评估、失败恢复和可观测证据。
- 解释 Agent Run 的最小闭环：目标 → 输入/上下文 → 计划 → 执行 → 工具/环境 → 输出 → 评估 → 记录；说明实际系统可循环，但本课实验固定为一次 run。
- 明确五个边界问题：谁定义目标、谁提供事实、谁允许行动、何时停止、谁判断成功。
- 增加“不是 Agent 的例子”和“接近 Agent 的例子”，避免只背定义。

### 3. 逐步拆解：阅读一条可验证的 Run

- 提供一条研究助手 run 的静态样例，包含 Run ID、目标、输入快照、步骤序号、决策、工具边界、停止条件、输出、评估和证据引用。
- 对样例逐段标注“这一段解决什么问题”和“缺失时会发生什么”，至少覆盖：目标模糊、输入漂移、无停止条件、无评估、无记录五类风险。
- 展示“看起来回答正确但不可验证”的失败样例，以及加入来源、约束、评估后的改写样例。

### 4. 研究助手 v0 设计实验

- 实验保持零网络、零账号、零 API key；资料 [S1]、[S2] 继续内联在页面中，不新增远程资源。
- 将任务合约从五要素扩展为可执行模板：目标/任务、输入、约束、允许动作、输出格式、成功标准、停止条件、证据记录，共八项。
- 提供可直接复制到本地文本文件的模板，建议文件名：`run-contract.md`、`input-freeze.md`、`run-log.md`、`evaluation.md`、`retrospective.md`。
- 实验分为准备、冻结、执行、评估、复盘五个阶段，每阶段列出动作、检查点、产物和常见错误。
- 执行仍为一次本地文本模拟：不调用远程模型；学习者可以人工完成或使用本地已有文本工具，但不得引入外部事实。
- 提供合格输出示例、故意失败输出示例和修复提示；失败示例至少覆盖无来源、超出边界、没有停止条件、没有评估记录四种情况。

### 5. 评估与复盘

- 增加 10 分评估量表：目标清晰 1 分、输入冻结 1 分、来源完整 2 分、约束遵守 1 分、输出结构 1 分、停止条件 1 分、证据记录 1 分、复盘具体 1 分；8 分及以上才算完成，低于 8 分必须重跑或修订。
- 提供逐项检查问题，并解释“通过/不通过”的判定依据，不能只显示口号式 checklist。
- 增加四道自测题，覆盖“为什么一次调用不是 Agent”“输入冻结解决什么风险”“没有评估会怎样”“何时应该停止”；提供折叠前可直接阅读的参考答案区，但不新增交互控件。
- 增加复盘模板：本次目标、最不确定处、一次失败或边界、证据、下一步改进。

### 6. 完成标准与下一课衔接

- 完成区明确“最低完成标准”“优秀完成标准”和“未完成时如何补救”。
- 明确五类交付物及其验收关系：合约对应设计，冻结记录对应输入，run log 对应执行，evaluation 对应判断，retrospective 对应学习闭环。
- 下一课仍只做文字预告“接入第一个 Tool”，不伪造工具、后端或下一课页面。

### 7. Visual / responsive / accessibility

- 复用现有六色 token、字体栈、卡片和代码块样式；通过章节编号、标签、对照表、时间线和示例块建立清晰层级。
- 桌面端内容宽度可读；390px 下所有表格转为可读的纵向或内部滚动布局，不产生页面级横向溢出。
- 使用语义化 `section`、`h2`/`h3`/`h4`、`ol`、`ul`、`table`、`pre`/`code`；表格提供 caption 或可读标题。
- 不新增网络请求、localStorage、第三方运行时依赖、动画或需要 JavaScript 状态的控件。

## Non-goals

- 不实现真实模型调用、Tool、Agent runtime、后端 API、登录、进度同步或数据库。
- 不补写构建路线或进阶路线第一课；`#first-lesson-builder` 与 `#first-lesson-advanced` 继续保持空锚点。
- 不删除 `src/task-board.ts` 或其独立纯函数测试。
- 不改动 `.harness/**` 运行事实、`.agents/**` skill、scripts、package manifest、index.html 或 public 资源。

## Acceptance Criteria

### AC-DEEP-001 课程完整性

第一课可见 section 包含课程定位、六段学习路径、学习目标、八项任务合约模板、五阶段实验、五类交付物、最低/优秀完成标准与补救路径；页面内容足以支持 60–90 分钟的学习活动，而不是只有概念摘要。

### AC-DEEP-002 概念与 run 证据

页面用对照表解释模型调用与 Agent Run 的至少七个差异，并提供一条包含目标、输入快照、步骤、边界、停止条件、输出、评估和证据的静态 run 样例；每个关键字段都有风险说明。

### AC-DEEP-003 可复制实验

页面提供五阶段实验说明和五个本地文本产物模板；资料边界仍为 [S1]/[S2]，实验不需要网络、账号、API key 或远程请求。

### AC-DEEP-004 失败学习与评估

页面包含至少四种失败样例及修复提示、10 分评估量表、四道自测题及参考答案、复盘模板；评估阈值和补救动作明确。

### AC-DEEP-005 行为与边界回归

既有路线切换、轨迹、能力地图、本周实验和 task-board 独立模块不回归；第一课不新增交互控件，不被路线切换移除或伪造 builder/advanced 内容；页面无 fetch、XMLHttpRequest、localStorage 或远程脚本。

### AC-DEEP-006 响应式与语义

桌面视口层级清楚；真实 390px 视口下页面无横向溢出，长代码/表格有内容级换行或局部滚动；保留 focus-visible 与 reduced-motion 行为。

### AC-DEEP-007 工程验证

`npm test`、`npm run typecheck`、`npm run build`、`bash scripts/check-repo.sh`（若被仓库既有 active DAG 阻断，必须分别报告运行态阻断与允许 active run 的项目检查结果）均有新鲜证据；浏览器验收覆盖桌面、390px、路线切换、锚点和 console/network/storage 边界。
