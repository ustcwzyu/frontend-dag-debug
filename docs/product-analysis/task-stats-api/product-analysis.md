# 产品分析：任务统计服务

## 1. 原始需求

原始需求见 `./source-requirement.md`。需求明确要求前端提交任务列表到后端统计接口，后端返回三个计数，前端在请求失败时保留本地统计并提示服务不可用。

## 2. 需求概述

这是一个无状态的本地演示 API 集成：前端任务看板继续负责任务编辑和 localStorage，后端只负责对请求中的任务快照计算统计结果。

## 3. 业务目标

- 为任务看板提供可独立验证的后端统计边界。
- 让用户同时看到服务统计状态和可用的本地兜底统计。
- 对无效输入给出可观察、稳定的 400 错误，而不是静默返回错误结果。

## 4. 需求分析

### 4.1 明确需求

- 前端和后端都在本需求范围内。
- API 为 `POST /api/v1/tasks/summary`，请求包含任务数组。
- 成功响应包含 `total`、`pending`、`done`。
- 空数组返回三个 0。
- 缺少数组或元素类型错误返回 `400 INVALID_TASKS`。
- 后端无认证、无数据库、无持久化；统计完全由请求体决定。
- 前端请求失败时保留本地计数并展示服务不可用提示。

### 4.2 推断需求

- 前端应在任务数据变化后触发同步请求，筛选按钮变化不应改变统计输入。
- 后端应限制请求体大小并拒绝深度异常或非 JSON 输入，避免本地服务被恶意大请求拖垮。
- 同一任务快照重复提交应返回相同结果，因为接口是无状态计算。

### 4.3 待确认问题

无。原始需求已明确范围、输入输出、错误、权限、持久化和兜底行为；示例使用推荐的本地演示默认值。

### 4.4 初步非目标

- 认证授权、数据库、任务写入、跨设备同步和生产部署。
- 分页、排序、搜索和任务详情接口。

## 6. 初步前端用户故事

### FE-US-001 展示服务任务统计

- 角色：任务看板使用者
- 目标：查看当前任务快照的服务统计，并在服务不可用时继续使用本地统计
- 价值：获得可验证的前后端统计结果，同时避免服务短暂不可用导致看板失去计数
- 入口：打开任务看板、添加任务、切换任务完成状态
- 验收关注点：成功、loading、服务错误、本地兜底、空列表和统计不受筛选影响

## 7. 初步前端输出规范

### FE-US-001 展示服务任务统计

- 页面/组件：任务看板统计区域
- 展示内容：服务统计的总数、待完成数、已完成数及服务状态提示
- 交互动作：任务变化后自动请求；筛选只改变列表，不改变统计输入
- UI 状态：normal、loading、success、error、empty
- 表单校验：沿用任务标题非空校验；统计请求发送合法任务快照
- 权限可见性：本地演示页面对所有访问者可见
- 边界处理：空列表显示 0；请求失败保留本地计数并提示；错误响应不得导致白屏

## 8. 初步后端用户故事

### BE-US-001 计算任务快照统计

- 系统能力：接收任务快照并返回聚合计数
- 使用方：任务看板前端
- 业务价值：提供独立、可重复验证的后端统计契约
- 触发方式：API
- 验收关注点：合法快照、空快照、非法输入、稳定错误结构、无状态幂等和请求大小保护

## 9. 初步后端输出规范

### BE-US-001 计算任务快照统计

- 输入语义：JSON 请求体包含 `tasks` 数组；每项包含字符串 `id`、字符串 `title`、布尔 `completed`
- 输出语义：HTTP 200 返回 `data.total`、`data.pending`、`data.done`
- 数据读写：只读请求体内存数据，不写数据库、文件或外部服务
- 权限规则：本地演示 API 不要求认证
- 业务规则：`total` 为任务数，`pending` 为 `completed=false` 数量，`done` 为 `completed=true` 数量
- 安全要求：仅接受 JSON；限制请求体大小；错误响应不包含堆栈
- 幂等与并发：相同任务快照重复请求结果一致；请求之间不共享可变统计状态
- 错误与边界：空数组返回 0；缺少数组或字段类型错误返回 400 和 `INVALID_TASKS`
