# 产品需求：任务统计服务

## 1. 需求概述

为任务看板增加一个无状态的后端统计能力。任务看板将当前任务快照发送给服务，服务返回总数、待完成数和已完成数；服务不可用时页面继续使用本地统计并提示状态。

## 2. 业务目标

- 建立前端与后端之间可重复验证的任务统计契约。
- 让用户在服务成功和服务失败两种状态下都能看到明确统计。
- 通过明确的 400 错误结构保护接口输入边界。

## 3. 需求范围

### 3.1 已确认需求

- 前端展示任务统计和服务状态。
- 后端提供 `POST /api/v1/tasks/summary`。
- 请求体为 `{ "tasks": [{ "id": string, "title": string, "completed": boolean }] }`。
- 成功响应为 `{ "data": { "total": number, "pending": number, "done": number } }`，HTTP 200。
- 空任务列表返回三个 0。
- 缺少 `tasks` 或任务元素字段类型错误返回 HTTP 400，错误为 `{ "code": "INVALID_TASKS", "message": string }`。
- 后端不要求登录、不保存任务、不访问数据库或外部服务。
- 前端请求失败时展示服务不可用提示并保留本地统计。

### 3.2 非目标

- 认证授权、数据库、任务写入、跨设备同步和生产部署。
- 分页、排序、搜索、任务详情和任务修改 API。

### 3.3 默认假设

- 本地 API 运行在 `http://localhost:3001`，前端开发页面运行在 Vite 默认地址。
- 服务统计请求使用当前任务快照；列表筛选不改变发送的任务集合。
- 请求体为 JSON，最大大小为 64 KiB；超过限制返回 400 `INVALID_TASKS`。

### 3.4 未决事项

无。

## 4. 业务规则

- `total` 等于 `tasks` 数组长度。
- `pending` 等于 `completed=false` 的任务数量。
- `done` 等于 `completed=true` 的任务数量。
- 相同任务快照重复提交返回相同结果。
- 后端错误不得泄露堆栈、环境变量或其他请求内容。
- 前端服务失败时不得清空本地任务或将本地计数替换为 0。

## 5. 决策追溯

本需求无澄清决策标记；范围和默认值均来自 `./source-requirement.md`。

## 6. 前端用户故事

### FE-US-001 展示服务任务统计

- 角色：任务看板使用者
- 目标：查看当前任务快照的服务统计，并在服务不可用时继续使用本地统计
- 价值：获得可验证的前后端统计结果，同时避免服务短暂不可用导致看板失去计数
- 入口：打开任务看板、添加任务、切换任务完成状态
- 验收标准：AC-FE-001、AC-FE-002

## 7. 前端输出规范

### FE-US-001 展示服务任务统计

- 页面/组件：任务看板统计区域
- 展示内容：总数、待完成数、已完成数和服务状态提示
- 交互动作：任务变化后自动请求统计；筛选只改变列表，不改变统计输入
- UI 状态：normal、loading、success、error、empty
- 表单校验：统计请求只发送合法任务快照；任务标题规则保持现有行为
- 权限可见性：本地演示页面对所有访问者可见
- 边界处理：空列表显示 0；失败时保留本地计数并提示；不得白屏

#### AC-FE-001 服务成功时展示后端统计

Given：
- 用户打开任务看板，当前任务快照包含 2 个待完成任务和 1 个已完成任务。
- 统计服务可访问并接受合法 JSON 请求。

When：
- 页面加载或任务状态变化触发统计请求。

Then：
- 页面展示服务返回的 `total=3`、`pending=2`、`done=1`。
- 请求进行期间展示 loading 状态，请求完成后显示 success 状态。
- 切换列表筛选按钮不会改变服务统计数字。

异常场景：
- 服务返回非 2xx 或网络失败时，页面保留最近一次本地统计并展示“统计服务暂不可用”提示，不得将数字静默清零。

#### AC-FE-002 空列表和服务失败可恢复

Given：
- 用户已打开任务看板，当前任务列表为空或统计服务暂时不可用。

When：
- 页面请求空列表统计，或用户在服务恢复后新增任务/切换任务状态。

Then：
- 空列表成功响应展示三个 0 和空状态。
- 服务恢复后下一次任务变化会重新请求，并展示新的服务统计。
- 页面保留任务输入、筛选状态和本地任务，不得因请求失败白屏或丢失数据。

异常场景：
- 服务返回错误 JSON 时，页面展示统一失败提示并继续使用本地统计；不得把错误堆栈展示给用户。

## 8. 后端用户故事

### BE-US-001 计算任务快照统计

- 系统能力：接收任务快照并返回聚合计数
- 使用方：任务看板前端
- 业务价值：提供独立、可重复验证的后端统计契约
- 触发方式：API
- 验收标准：AC-BE-001、AC-BE-002

## 9. 后端输出规范

### BE-US-001 计算任务快照统计

- 输入语义：JSON 请求体包含 `tasks` 数组；每项含字符串 `id`、字符串 `title`、布尔 `completed`
- 输出语义：HTTP 200 返回三个整数统计字段
- 数据读写：只读请求体，不写持久化介质
- 权限规则：本地演示 API 不要求认证
- 业务规则：按 `completed` 聚合 total/pending/done
- 安全要求：只接受 JSON、限制 64 KiB 请求体、错误不泄露堆栈
- 幂等与并发：相同快照重复请求结果一致，请求之间无共享可变统计状态
- 错误与边界：空数组返回 0；非法结构返回 400 `INVALID_TASKS`

#### AC-BE-001 合法任务快照返回统计

Given：
- 请求体是合法 JSON，包含 2 个 `completed=false` 任务和 1 个 `completed=true` 任务。

When：
- 客户端调用 `POST /api/v1/tasks/summary`。

Then：
- 服务返回 HTTP 200。
- 响应 JSON 为 `{ "data": { "total": 3, "pending": 2, "done": 1 } }`。
- 服务不写入任务数据，也不依赖上一次请求的状态。

异常场景：
- `tasks` 为空数组时返回 HTTP 200，三个统计字段均为 0；响应不得包含 NaN、负数或堆栈。

#### AC-BE-002 非法任务快照返回稳定错误

Given：
- 请求缺少 `tasks`，或某个任务的 `id`、`title`、`completed` 类型不符合契约，或请求体超过 64 KiB。

When：
- 客户端调用 `POST /api/v1/tasks/summary`。

Then：
- 服务返回 HTTP 400。
- 响应包含 `code=INVALID_TASKS` 和非空 `message`。
- 服务不返回统计结果，不写入持久化数据。

异常场景：
- 请求不是合法 JSON 时同样返回 HTTP 400 `INVALID_TASKS`，且响应不得包含内部错误堆栈或原始请求内容。
