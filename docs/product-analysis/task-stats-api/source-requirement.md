# 任务统计服务需求（原始输入）

## 目标

为现有任务看板增加一个可调用的后端统计接口。前端将当前任务列表提交给服务，服务返回总数、待完成数和已完成数，页面展示服务统计；服务不可用时继续展示本地统计并提示用户。

## 范围

- 前端：在任务看板增加“服务统计”状态展示，并在新增任务、切换完成状态、筛选变化后同步请求统计接口。
- 后端：提供 `POST /api/v1/tasks/summary`，校验任务列表并返回统计结果。
- 验证：覆盖成功请求、空列表、非法任务数据、服务不可用时的前端兜底。

## 明确契约

- 请求体为 `{ "tasks": [{ "id": string, "title": string, "completed": boolean }] }`。
- 成功响应为 `{ "data": { "total": number, "pending": number, "done": number } }`，HTTP 200。
- 空任务列表返回三个 0。
- 缺少 `tasks` 或任务元素字段类型错误时返回 HTTP 400，错误结构为 `{ "code": "INVALID_TASKS", "message": string }`。
- 本地演示服务不要求登录，不保存任务，不访问数据库；每次请求只基于请求体计算。
- 前端请求失败时显示服务不可用提示，但保留并展示本地统计。

## 非目标

- 不新增用户认证、权限系统、数据库、任务同步或跨设备持久化。
- 不改变现有任务创建、筛选、localStorage 持久化和问候弹窗行为。
