# 产品需求：第一课学习会话记录器

## 1. 需求概述

在 Agent 学习实验室首页新增「学习会话工作台」独立区块（位于 progress-panel 之后）：按八步闭环逐项勾选、编辑五份模板草稿（run-contract / input-freeze / run-log / evaluation / retrospective，完成=修改过预填骨架）、10 分量表自评、本地累计会话计时与摘要；草稿自动保存到 localStorage；登录后可将完成状态与自评分合并同步到现有 `/api/v1/progress`（保留 weeklyLabCompleted）。纯前端实现，不改后端与既有模块。

## 2. 业务目标

- 将第一课从纯阅读升级为可执行的练习工作台，用户产出五份本地文件骨架。
- 工作台状态（草稿、步骤勾选、自评、计时）刷新不丢失。
- 进度同步不破坏既有数据：仅更新 firstLessonCompleted / evaluationScore，保留 weeklyLabCompleted。
- 验证本项目新增的前端实现工作流（frontend-implementation 任务类型全链路）。

## 3. 需求范围

### 3.1 已确认需求

- 工作台区块：位于 progress-panel 区块之后，独立 section；不修改课程区（first-lesson-beginner）内容。
- 八步闭环引导：八步列表来源于第一课内容中的八步闭环（ol.lesson-loop），每步可勾选完成，全部勾选给出完成提示。
- 五模板草稿：预填骨架文本（与课程区模板一致），textarea 可编辑；完成判定=草稿文本 trim 后与骨架文本不同（DEC-Q-002）；展示 X/5 完成计数。
- 10 分量表自评：0–10 整数输入，允许为空。
- 会话计时：开始/暂停/继续/重置，累计时长随草稿持久化，展示于摘要页；不同步服务端（DEC-Q-004）。
- 摘要页：步骤完成 X/8、模板完成 Y/5、自评分、累计时长、最近保存时间。
- 草稿持久化：localStorage 自动保存与恢复；完成后可重置清空。
- 进度同步：合并后再 PUT（DEC-Q-003）——GET 现有进度 → 保留 weeklyLabCompleted → 更新 firstLessonCompleted 与 evaluationScore → PUT；未登录禁用同步并提示登录；失败保留本地草稿。
- 同步成功判断：八步全部勾选且五模板全部完成且自评分非空时，firstLessonCompleted=true；否则按现有逻辑更新。
- 既有约束保持绿：main.ts 不得新增 fetch(/localStorage/XMLHttpRequest/location.reload 字面量；存储收敛于 auth.ts 与新模块；课程区源码区间无交互控件；style.css 不新增 @keyframes；homepage.test.mjs / frontend-api.test.mjs / task-board / server-api 测试零修改通过。

### 3.2 非目标

- 不改后端：无新端点、不改 server/**、不改 api.ts / auth.ts / task-board.ts / types.ts。
- 不改现有进度面板（progress-panel）行为。
- 不修改第一课课程阅读区内容（id=first-lesson-beginner 内部静态 HTML 原样保留）。
- 不做富文本编辑、文件下载、多用户协作、AI 生成建议。

### 3.3 默认假设

- 工作台数据源：八步文本与五模板骨架从课程内容（API 或兜底）同源提取；骨架文本须与课程区 `<pre>` 内容一致。
- 工作台草稿存储 key 与既有 key 严格区分（不与 frontend-dag-debug:tasks / frontend-dag-debug:auth 冲突）。
- 同步时若 GET 失败或未登录，不执行 PUT，保留本地状态并提示。
- 自评分 0–10 校验与进度面板一致；评估分输入为空时不写入 evaluationScore（保持服务端原值）。

### 3.4 未决事项

无。

## 4. 业务规则

- 模板完成判定（BR-JOURNAL-001）：草稿文本 trim 后与骨架文本 trim 后不同 ⇒ 该模板完成；完全相同或为空 ⇒ 未完成。逐模板独立判定。
- 完成度汇总（BR-JOURNAL-002）：步骤 X/8、模板 Y/5 实时计算展示；X=8 且 Y=5 且自评分非空 ⇒ 可判定第一课完成。
- 同步语义（BR-JOURNAL-003）：PUT 请求体 = { firstLessonCompleted, evaluationScore, weeklyLabCompleted }，其中 weeklyLabCompleted 取 GET 结果原值；不可整体覆盖。
- 持久化语义（BR-JOURNAL-004）：草稿改动即保存到 localStorage（可防抖）；加载时自动恢复；重置仅清空工作台自身 key，不得触碰其他 key。
- 失败语义（BR-JOURNAL-005）：同步失败不清空草稿、不改变步骤勾选，仅提示并保留本地值。
- 隔离语义（BR-JOURNAL-006）：工作台所有持久化与交互不得影响第一课阅读区、进度面板、任务看板。

## 6. 前端用户故事

### FE-US-001 八步闭环引导工作台

- 角色：学习第一课的用户
- 目标：在工作台按八步闭环逐项勾选完成进度
- 价值：把八步闭环从阅读材料变成执行清单
- 入口：工作台区块（progress-panel 之后）
- 验收标准：AC-FE-001、AC-FE-002

### FE-US-002 五模板草稿编辑与完成度校验

- 角色：学习第一课的用户
- 目标：编辑五份模板草稿，明确哪些已完成
- 价值：五份交付物落地，完成度可视化
- 入口：工作台模板区
- 验收标准：AC-FE-003、AC-FE-004、AC-FE-005

### FE-US-003 自评、计时与摘要

- 角色：学习第一课的用户
- 目标：自评 10 分量表，查看会话时长与整体摘要
- 价值：形成可归档的学习会话记录
- 入口：工作台摘要区
- 验收标准：AC-FE-006、AC-FE-007

### FE-US-004 草稿持久化与进度同步

- 角色：已登录/未登录用户
- 目标：刷新不丢草稿；登录后同步到服务端进度
- 价值：草稿与进度双保险，不同设备可恢复
- 入口：工作台同步区
- 验收标准：AC-FE-008、AC-FE-009、AC-FE-010

## 7. 前端输出规范

### FE-US-001 八步闭环引导工作台

- 页面/组件：首页新 section「学习会话工作台」
- 展示内容：八步列表（勾选框 + 步骤文本）、步骤完成计数、全部完成提示
- 交互动作：勾选/取消勾选；全部勾选后展示「八步全部完成」状态
- UI 状态：每步 checked/unchecked；计数实时更新
- 表单校验：无（勾选无校验）
- 权限可见性：所有访问者可见
- 边界处理：勾选状态随草稿持久化；重置可清空

#### AC-FE-001 展示八步闭环并可勾选

Given：
- 用户打开首页并滚动到学习会话工作台。

When：
- 页面加载完成。

Then：
- 工作台展示八步闭环列表，步骤文本与课程区八步闭环一致（目标、输入/上下文、计划、执行、工具/环境、输出、评估、记录）。
- 每步有独立勾选控件；初始状态全部未勾选。
- 勾选任意步骤后，该步骤状态变为已勾选，步骤计数随之更新。

异常场景：
- 课程内容加载失败（降级模式）时，工作台仍可从兜底内容提取八步文本并展示，页面不报错、不白屏。

#### AC-FE-002 全部勾选给出完成提示

Given：
- 工作台八步列表已展示。

When：
- 用户将八步全部勾选。

Then：
- 步骤计数显示 8/8。
- 页面展示「八步全部完成」类提示。

异常场景：
- 用户取消任一勾选后，完成提示消失，计数回到 7/8。

### FE-US-002 五模板草稿编辑与完成度校验

- 页面/组件：工作台模板区
- 展示内容：五份模板（run-contract / input-freeze / run-log / evaluation / retrospective），每份含名称、骨架预填 textarea、完成标记
- 交互动作：编辑 textarea；失焦/防抖自动保存；逐模板完成标记实时更新
- UI 状态：模板未完成/已完成（按 BR-JOURNAL-001）；整体计数 Y/5
- 表单校验：无强制校验（完成判定仅比较文本）
- 权限可见性：所有访问者可见
- 边界处理：草稿空时视为未完成；刷新后恢复已编辑内容

#### AC-FE-003 预填骨架并可编辑

Given：
- 工作台模板区已渲染。

When：
- 用户查看任意模板草稿。

Then：
- 该模板 textarea 预填与课程区一致的骨架文本（run-contract / input-freeze / run-log / evaluation / retrospective 各一份）。
- 用户可自由编辑文本内容。

异常场景：
- 课程内容加载失败时，骨架从兜底内容提取，五份模板仍然齐全。

#### AC-FE-004 修改过骨架才算完成

Given：
- 五份模板草稿均已预填骨架。

When：
- 用户未修改某模板（保留骨架原样）。

Then：
- 该模板完成标记为未完成，模板计数不计入。

异常场景：
- 用户删除全部文本（草稿为空）时，该模板同样视为未完成。

#### AC-FE-005 修改后完成标记与计数更新

Given：
- 用户在某模板中输入了与骨架不同的内容。

When：
- 用户继续修改或保存草稿。

Then：
- 该模板完成标记变为已完成。
- 模板计数实时更新（如 1/5 → 5/5）。

异常场景：
- 用户把修改内容删回与骨架完全一致时，完成标记回到未完成，计数相应减少。

### FE-US-003 自评、计时与摘要

- 页面/组件：工作台摘要区（自评输入 + 计时器 + 摘要）
- 展示内容：10 分量表自评输入（0–10）、计时器（当前时长与开始/暂停/继续/重置按钮）、摘要（步骤 X/8、模板 Y/5、自评分、累计时长、最近保存时间）
- 交互动作：输入自评分；开始/暂停/继续/重置计时；摘要随状态实时更新
- UI 状态：计时运行/暂停；摘要显示最新值
- 表单校验：自评分必须为 0–10 整数或空
- 权限可见性：所有访问者可见
- 边界处理：计时值随草稿持久化，刷新后恢复；自评分非法输入不保存

#### AC-FE-006 自评输入 0–10 校验

Given：
- 摘要区自评输入已渲染。

When：
- 用户输入 0–10 的整数。

Then：
- 该值被接受并计入摘要。

异常场景：
- 用户输入 11、-1 或小数（如 7.5）时，输入被拒绝或提示范围错误，摘要不采用该值。

#### AC-FE-007 计时开始/暂停/继续/重置

Given：
- 工作台计时器已渲染，初始时长为 00:00。

When：
- 用户点击开始。

Then：
- 时长开始累计；点击暂停后时长停止；点击继续后从暂停处继续累计；点击重置后归零。

异常场景：
- 刷新页面后，计时状态与累计时长从草稿恢复（运行中则从恢复时刻继续累计）。

#### AC-FE-008 摘要展示完整会话记录

Given：
- 用户已勾选部分步骤、完成部分模板、填写自评分。

When：
- 用户查看摘要区。

Then：
- 摘要展示步骤 X/8、模板 Y/5、自评分、累计时长与最近保存时间，数值与当前工作台状态一致。

异常场景：
- 自评分为空时，摘要显示「未自评」类占位，不显示无效数字。

### FE-US-004 草稿持久化与进度同步

- 页面/组件：工作台持久化与同步区
- 展示内容：保存状态提示、最近保存时间、同步按钮与状态、登录提示
- 交互动作：草稿自动保存；登录后点击同步写入服务端；未登录时同步按钮禁用
- UI 状态：saved/saving/sync-failed/logged-out/synced
- 表单校验：同步前校验完成条件（八步全勾选、五模板完成、自评分非空才置 firstLessonCompleted=true）
- 权限可见性：同步仅登录用户可执行；草稿编辑所有人可用
- 边界处理：同步失败保留本地草稿并提示；未登录仅提示

#### AC-FE-009 草稿自动保存与恢复

Given：
- 用户在工作台编辑草稿、勾选步骤、设置计时。

When：
- 用户刷新页面或关闭后重新打开。

Then：
- 工作台恢复全部草稿内容、步骤勾选、自评分与累计时长。
- 存储 key 与既有 key（任务看板、会话）严格区分，不互相影响。

异常场景：
- localStorage 不可用或被清空时，工作台以初始空状态加载，页面不报错。

#### AC-FE-010 登录后合并同步到服务端

Given：
- 用户已登录，工作台存在草稿状态，服务端已有该用户进度。

When：
- 用户点击同步按钮。

Then：
- 页面先读取服务端现有进度，再 PUT 更新（firstLessonCompleted 按完成条件置位，evaluationScore 采用自评分，weeklyLabCompleted 保留服务端原值）。
- 同步成功后展示成功状态与时间；同步失败展示失败提示且本地草稿保持不变。

异常场景：
- 未登录时同步按钮禁用，并提示「登录后同步」。
- 服务端 GET 失败时不做 PUT，保留本地状态并提示失败原因。
- 用户服务端已有 weeklyLabCompleted=true 时，同步后该值仍为 true（不被覆盖）。
