# 原始需求：为 Agent 学习实验室加上后端

## 用户原始表达

用户要求：「帮我这个项目加上后端」。

经澄清确认的完整需求：

1. **交付形态**：完整 API 服务——数据 API + 持久化 + 前端改造，构成完整前后端项目。
2. **技术栈**：Node.js + Express（与现有 TypeScript/Vite 同语言）。
3. **持久化**：SQLite。
4. **内容后端化范围**：全部内容 API 化——路线（入门/构建/进阶）、能力地图（六类）、本周实验、第一课完整课程内容均从后端接口获取。
5. **学习进度**：简易账号登录体系（本地演示用），登录后可保存个人学习进度。
6. **降级策略**：后端服务不可用时前端回退到内联数据兜底，页面照常可用并提示「服务不可用」。
7. **契约变化**：接受——现有首页测试中「零网络请求、课程数据内联」断言将更新，站点由「零后端」变为「有后端」。

## 原始约束

- 带后端接口的需求必须先提供原始需求文档；随后按 Product Requirement → dependency-analysis → api-documentation → DAG 生成可追溯输入。
- 不得臆造 API 契约，所有契约以经确认的文档为准。
- 实现必须经过本仓库 loop-agent 治理 DAG，主会话不得直接修改业务实现。
