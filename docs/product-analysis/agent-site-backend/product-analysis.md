# Product Analysis：Agent 学习实验室后端服务

## 原始需求

用户原始表达：「帮我这个项目加上后端」。经澄清确认：交付完整 API 服务（数据 API + 持久化 + 前端改造），Node.js + Express 技术栈，SQLite 持久化，全部内容 API 化，简易账号登录记录学习进度，后端不可用时前端降级内联兜底；接受「站点由零后端变为有后端」的契约变化（现有测试断言更新）。

## 需求概述

为当前的零后端静态单页站（Agent 学习实验室：三条学习路线、六类能力地图、本周实验、入门第一课完整课程）增加 Express + SQLite 后端：课程内容数据从内联源码迁移为后端 API 提供；新增简易账号体系与应用内学习进度持久化；前端在 API 可用时使用服务数据、不可用时回退内联数据并提示服务不可用。

## 业务目标

- 让站点从「零后端演示页」演化为「可验证的完整前后端项目」，课程内容、账号、进度均有服务端职责。
- 用 SQLite 真实持久化学习进度，重启服务不丢失。
- 后端不可用或未登录时站点仍可浏览，不白屏、不静默失败。

## 需求分析

### 明确需求

- 后端技术栈：Node.js + Express，TypeScript；持久化：SQLite。R1（原始需求+澄清 DEC-Q-002/DEC-Q-003）
- 全部内容 API 化：三条路线、六类能力、本周实验、第一课课程内容均由后端接口提供；前端加载成功后用服务数据渲染。R2（DEC-Q-004）
- 简易账号登录（本地演示，无邮箱/找回密码），登录后保存个人学习进度；进度字段含第一课完成状态、第一课评估分、本周实验完成标记。R3（DEC-Q-005）
- 后端服务不可用时前端回退内联数据兜底，页面可用并提示「服务不可用」；进度保存失败仅提示，不清空本地状态。R4（DEC-Q-006）
- 现有首页测试「零网络请求、课程数据内联」断言更新为新契约。R5（澄清确认接受契约变化）
- 本地开发：前端 Vite dev 与后端 3001 端口并存，`/api` 由 Vite 代理；生产构建后同一 Node 进程可同时提供静态资源与 API。R6（推断，由完整前后端项目目标推导）

### 推断需求

- 账号密码不得以明文存储（表达为单向散列）。R7（推断：简易登录仍须避免明文口令入库）
- 进度与账号数据按用户隔离，未登录不可读写他人进度。R8（推断）
- 内容数据在服务首次启动时自动初始化，内容源由服务端持有（不再内联于前端）。R9（推断）

无。所有 P0/P1 决策已在澄清轮次确认，见 `requirement-clarification.md`。

## 初步前端用户故事

### FE-US-001 服务化课程内容与降级兜底

- 角色：浏览 Agent 学习实验室的用户
- 目标：看到由后端提供的路线/能力/实验/第一课内容；后端不可用时仍能浏览
- 价值：内容由服务端契约提供，部署与更新内容不再依赖前端发版
- 入口：页面加载、刷新、路线切换（切换仍本地即时同步）
- 验收关注点：加载成功用服务数据渲染；失败回退内联数据并出现「服务不可用」提示；页面不白屏；内容结构与现状一致

### FE-US-002 简易账号登录

- 角色：希望保存学习进度的用户
- 目标：注册/登录后获得会话，用于保存个人进度
- 价值：进度与设备解耦，换浏览器/换设备可恢复
- 入口：站点头部或进度面板的登录表单
- 验收关注点：注册与登录成功获得令牌并持久化会话；失败给出可读错误；未登录状态清晰可辨

### FE-US-003 学习进度保存与恢复

- 角色：已登录用户
- 目标：保存第一课完成状态、评估分、本周实验完成标记，再次登录后恢复
- 价值：学习状态可恢复、可归档
- 入口：进度面板
- 验收关注点：登录后加载服务端进度并回填；修改后保存成功有确认；保存失败仅提示并保留本地值；退出登录后进度面板恢复未登录态

## 初步后端用户故事

### BE-US-001 提供课程内容 API

- 系统能力：以 API 提供路线、能力地图、本周实验、第一课内容
- 使用方：站点前端（含降级路径）
- 业务价值：内容由服务端持久化持有，前端可校验契约
- 触发方式：API
- 验收关注点：各端点返回契约规定的数据；builder/advanced 无课程内容返回明确 404；错误结构统一

### BE-US-002 提供账号注册登录与会话

- 系统能力：注册账号、密码登录、签发会话令牌
- 使用方：站点前端
- 业务价值：为进度持久化提供用户身份边界
- 触发方式：API
- 验收关注点：用户名唯一；密码单向散列；口令错误返回统一错误；令牌可校验归属

### BE-US-003 提供按用户隔离的学习进度持久化

- 系统能力：读写指定用户的进度
- 使用方：站点前端（已登录）
- 业务价值：进度真实落库，重启不丢
- 触发方式：API
- 验收关注点：未认证请求被拒；进度按用户隔离；字段校验失败返回 400；更新后读取为新值
